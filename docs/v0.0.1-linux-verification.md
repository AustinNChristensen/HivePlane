# v0.0.1 Linux verification runbook

The HivePlane code paths that talk to systemd-user (`packages/cli/src/service.ts`,
`packages/cli/src/index.ts`, the `infra/install/systemd/*.tmpl` files) are
covered by unit tests with a mocked `node:os.platform`, but they have **not**
been smoke-tested on a real Linux box at v0.0.1. This document is the
end-to-end checklist a maintainer should walk through before tagging the
release; it doubles as the closing condition for
[#51](https://github.com/AustinNChristensen/HivePlane/issues/51).

The Bee path is the higher-risk side (more lifecycle methods exercised). The
Hive path mirrors the Bee path structurally, so a Bee pass plus a Hive
install/start/stop is a sufficient signal.

## Targets

Run on at least one mainstream distro. Suggested order, easiest first:

1. **Ubuntu 22.04 LTS** or **24.04 LTS** — primary target; most common
   `systemctl --user` setup.
2. **Debian 12 (bookworm)** — same systemd era as Ubuntu but minimal default
   install; surfaces missing-package issues.
3. **Fedora 40** — newer systemd; surfaces journald-related drift.

Skip WSL1 — it has no systemd-user instance. WSL2 is fine but treat it as a
separate target since reboot survival semantics differ.

## Prerequisites on the target machine

- Node 20+ (`node -v`).
- `git` on PATH.
- A reachable Hive (any Mac / Linux box; can be the same machine for a
  loopback smoke).

## Bee path

### 1. Install

```sh
curl -fsSL <hive>/install/bee.sh | sh
```

**Expect:**

- The script ends with the green `Bee installed.` banner.
- Final line for Linux specifically: `Linux: for the daemon to survive reboot
you need linger enabled once: loginctl enable-linger <user>`.
- `~/.local/bin/hive` exists and is executable.
- `~/.hiveplane/bee-identity.json` exists.

### 2. Login + start

```sh
# from a Hive, mint a token (or grab a pairing key from the dashboard)
TOKEN=$(curl -fsSL -X POST http://<hive>:8787/api/bootstrap-tokens \
  -H "Authorization: Bearer $HIVEPLANE_ADMIN_TOKEN" \
  -H "content-type: application/json" -d '{"beeName":"linux-test"}' | jq -r .token)

hive login http://<hive>:8787 --name linux-test --token "$TOKEN"
hive start
```

**Expect:**

- `hive start` prints `Installed service unit (linux): <path>` followed by
  `Started. Tail logs with hive logs -f.`
- If linger is off, `hive start` prints the linger nudge with the exact
  `loginctl enable-linger` command to copy.

**Verify:**

```sh
test -f ~/.config/systemd/user/hiveplane-bee.service   # unit file present
systemctl --user is-active hiveplane-bee.service       # → active
systemctl --user status hiveplane-bee.service --no-pager
hive status                                            # shows installed,running
hive logs -f                                           # tail journald output
```

### 3. End-to-end: Bee shows up in dashboard

In a browser, open `http://<hive>:8787/`, paste the admin token, watch the
Bees tab. The new `linux-test` Bee should appear with `online` status and
its heartbeat counter should tick up every 10 seconds.

### 4. Reboot survival

```sh
loginctl enable-linger $(id -un)    # if not already on
sudo reboot
```

After the box comes back up, **without logging in via SSH first** if you can
manage it (some setups let the journal of the next boot show whether the
service started before login):

```sh
ssh <bee>
systemctl --user is-active hiveplane-bee.service
hive status
```

**Expect** the unit to be `active` immediately, and the dashboard's heartbeat
counter to be ticking from a low value (i.e. the service started after boot,
not from when you logged in).

### 5. journalctl-missing fallback

This is hard to reproduce on a normal distro — but the fallback is exercised
on minimal containers. If you have a Docker host:

```sh
docker run -it --rm ubuntu:22.04 bash
# inside the container — apt without systemd-journal-remote:
apt-get update && apt-get install -y curl
# install + login + start (start will fail because no user systemd in this
# environment, which is the expected unsupported-platform behavior).
```

The point of this check is just that `hive logs` should not blow up with
`spawn ENOENT: journalctl` on a host that doesn't ship `journalctl`. It now
prints `journalctl not on PATH; falling back to file logs at <dir>` and
shows the file-based output (or "No log file at … yet" if the daemon never
ran).

### 6. Cleanup

```sh
hive stop
hive disable
test ! -f ~/.config/systemd/user/hiveplane-bee.service
hive logout
```

## Hive path

Pick a Linux box (can be the same as the Bee target — different systemd
labels mean they coexist):

```sh
curl -fsSL https://raw.githubusercontent.com/AustinNChristensen/HivePlane/main/infra/install/hive.sh | sh
```

**Expect:**

- The script writes `~/.hiveplane/hive-config.json` with mode `0600`.
- `~/.config/systemd/user/hiveplane-hive.service` exists.
- `systemctl --user is-active hiveplane-hive.service` is `active`.
- `hive selfhost status` shows `installed, running`.
- `curl http://localhost:8787/healthz` returns `{"ok":true,...}`.

Reboot the box; confirm the Hive comes back without manual intervention.

```sh
hive selfhost stop
hive selfhost uninstall
test ! -f ~/.config/systemd/user/hiveplane-hive.service
```

## What to file

If any of the steps above fails:

- File a separate issue per failure mode (don't overload #51 with a list).
- Tag the issue `area:daemon` (Bee) or `area:control-plane` (Hive),
  `area:provisioning`, `priority:p0`, `type:bug`.
- Include the distro, kernel (`uname -a`), `systemd --version`, and the
  exact command + output that failed.

If the smoke passes end-to-end:

- Comment on [#51](https://github.com/AustinNChristensen/HivePlane/issues/51)
  with the distro(s) you tested and close the issue.
- That closes the last open item on the v0.0.1 milestone.
